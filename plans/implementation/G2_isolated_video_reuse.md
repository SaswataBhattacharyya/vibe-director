## Dependency, persistence and boundary

Minimal compiler closure: `minimax_h3_t2v.py` → `minimax_h3_graph_compiler.py` → exact API graph JSON. Readiness keeps existing model/file/node/flag/smoke checks while replacing only the large `audio_catalog` root locator with `COMFYUI_ROOT`. Worker closure is the selected production worker, ledger, authority, reconciliation, `media_jobs`, GPU runtime/watchdog and standard-library dependencies. The isolated output collector is new; it does not copy `production_take_runtime` or `production_assets` wholesale.

The project-scoped `validate_and_compile_shot` route (`services/production_shot_validation.py:23–49`) dispatches zero-ref plans directly to `compile_t2v_graph`, so it reuses T2V checks but still carries project/run/shot identity. The general `validate_reference_plan` limits (including 5–15 sec, steps 8–40 and uint32 seed at `minimax_h3_graph_compiler.py:156–175`) are R2V checks and are not automatically applied to T2V. The T2V compiler itself visibly writes steps/seed without validating their bounds. No inspected MiniMax T2V path enforces the product <7000-character prompt requirement; the new isolated validator must. The CPU adapter fixes `steps=20` and `seed=1` for its first slice; editable steps/seed are deferred pending a reviewed T2V capability contract. This is an adapter constraint, not a claim that the T2V compiler enforces those values.

Product SQLite lives under `<VIBE_DIRECTOR_DATA_DIR>/storage/production/ledger.sqlite3` by default; `VIBE_DIRECTOR_LEDGER_PATH` may override only inside that root. The localhost server never starts dispatch. A worker starts with explicit `--enable-worker` or `VIBE_DIRECTOR_ENABLE_WORKER=1`; API capability includes worker status and POST fails closed without a healthy consumer. The worker gates queued claims and checks readiness again in prepare; the source worker retains Comfy queue/GPU/watchdog/unknown-submit safeguards. Outputs are ffprobe-checked and stored beneath the product root with public asset URLs and hidden filesystem paths. No live Comfy execution was performed.

Implemented local draft API routes (not yet deployed or browser-connected):

- `GET /api/video/capabilities` — source T2V capability plus live GPU guard and worker dispatch heartbeat; unavailable if the worker is not explicitly running and healthy.
- `POST /api/video/validations` — CPU request normalization and graph preview; does not probe or submit.
- `POST /api/video/jobs` — explicit Generate creating one durable, idempotent isolated job only when readiness and consumer checks pass.
- `GET /api/video/jobs/{job_id}`, `/events`, and `/api/video/jobs/by-idempotency/{key}?workspace_id=...` — read-only retrieval and lost-response recovery.
- `POST /api/video/retakes/{job_id}` — read-only draft with saved request and explicit retention choice; a separate job POST is required to submit.
- `POST /api/video/jobs/{job_id}/accept` and `GET /api/video/assets/{asset_id}` — accept reviewable output and serve product-owned playback bytes with range requests.

One idempotency key maps to one application `job_id` and immutable input snapshot; every Comfy submission has reserved `prompt_id`; every output has stable `asset_id` and take/attempt provenance. Browser reconnect performs GET/reconciliation only; it never implicitly POSTs.

- **Do not copy:** whole Story Builder app, legacy Generate/Production V2 pages, OpenMontage/AGPL code, ComfyUI installation/model weights, media, secrets, node packs, environments, arbitrary workflows, R2V/FLF compilers, or GPU setup.
- **CPU and durable backend implemented in this draft:** exact compilers/graph; strict request contract and pinned preview; shared-ledger isolated identity/idempotency; opt-in worker/API; lost-response lookup; recovery-safe execution; output collection/playback routes; immutable retake snapshots and explicit retention choice. Focused checks use CPU fixtures/fake Comfy responses only.
- **Still required:** connect the UI to agreed fields, review browser usability/reconnect, check current graph/model/node/smoke/GPU readiness, and conduct supervised user-clicked real output/playback/retake acceptance. - **License/notices:** local reference tree has no root license and no Git metadata; the pinned upstream root had no `LICENSE` or `NOTICE`, and the three selected source files have no explicit license header. The owner authorized reuse of their own source for this bounded slice. No third-party implementation was imported. Preserve and confirm notices during canonical integration. ## Acceptance boundary

The 19 focused standard-library tests verify contract/compile boundaries, ledger/idempotency/restart behavior, retake snapshot rules, worker-dispatch gating and unknown-submit handling with injected fakes. They do not prove real workflow readiness, rendered output, collection/playback, real restart recovery, or browser usability. Real-runtime acceptance separately requires supervised ComfyUI/GPU admission, exact installed graph/nodes/models and smoke, native media probe/playback, reload recovery and a preserved-input retake. No render was run.
