# Style learning
/addstyle creates a unique empty named profile; /style selects one without sending the chat. Each style starts fresh. Only confirmed preferences are applied, across this user's projects, with project overrides. Do not modify global Codex skills.
Propose concise rules from explicit owner feedback with provenance. Confirm before reuse; offer inspect, edit, forget and reset. Never copy tastes, examples or vague-phrase interpretations between styles. Verified asset identities, availability and paths may be shared through the shared library. A factual path is not evidence of a preference.
Pin style ID and memory version into every proposed/approved revision and job. Later memory changes cannot mutate an in-flight edit. Ask fewer questions when confirmed rules resolve ambiguity; keep both clearances permanently.
