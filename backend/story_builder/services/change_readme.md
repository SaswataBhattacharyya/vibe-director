# Backend services — active capability / Editor / production integration (2026-11-07)

Current implementation guides: `fixes/ACTIVE_FIXES.md`, `fixes/INTEGRATION_ARCHITECTURE.md`, `fixes/ACCEPTANCE_TESTS.md`. Old R01/R02 crash-recovery and Editor brief bridge are **already source-implemented**; don't replay them.

- `agent_tools.py`: passive metadata + readiness for seven allowlisted actions: MP3, last-frame, Editor brief, Codex computer, complete-source transcription, denoising and CPU stems; includes input/scope/runtime/result/approval contracts. Not a comprehensive app tool registry.
- `agent_conversation.py`: shared Director with finite intent schema and existing bounded Story/Screenplay/Image/Prompt/Video/Studio/ACE proposal/discussion adapters. Uses live readiness when proposing media operations, resolves Editor sources separately from edit ranges and supplies verified completed speech evidence to follow-up chat/briefs. It does **not** dispatch every app feature or approve/render edits automatically.
- `agent_tasks.py` / `agent_editor.py`: durable approved operations and revision-scoped brief preparation. Add additional narrow typed validators only for real installed capabilities; retain actual job state, approve/review steps, owner/hash and repeated-request recovery. Never add generic arbitrary command endpoints.
- `audio_utilities.py`: existing MP3, denoiser and Demucs execution reused through approved task correlation. Director stems are CPU-only; denoiser retains existing GPU admission.
- `agent_transcription.py`: installed offline CPU Whisper image/model, whole-source decode, source-relative segment/word timing/confidence, strict result validation, private temporary staging and owned-container cancellation. `video_repertoire.py`/worker register the durable CPU job without acquiring a GPU slot. Actual synthetic WAV and 9.85s MP4 analysis passed; confidence alone is not gibberish detection. Reviewed segment cuts now use `editor_speech.py`; synthetic CPU render acceptance passed. Owner-content speech judgments remain a playback review step.
- `vibe_editor.py` / `vibe_editor_api.py` / `vibe_editor_render.py`: saved Editor session, ranges, plan revisions, two clearances and trusted JSON→HyperFrames renderer; visual Studio UI must translate into this format or a separately validated, versioned adapter. No arbitrary provider-authored HTML/JS.
- `media_library.py` / `storage_paths.py` / `projects.py`: preserve existing project-scoped IDs, linked storage, source hashes, explicit import, deletion checks, output grants and checkpoint recovery. Index/membership migrations require separate schema impact proof.
- `storyboard.py` / `production_manifest.py`: preserve the native storyboard; metadata-only version-1 export pins Backlot revision d21f5d4eaa08 and checks saved revision, owned asset IDs and source hashes. No media copying, upstream installation, write-back or second project database. Production Board remains open.
- **Runtime skill dependency:** `agent_skills.py` points into `fixes/vibe-director-codex-agent-blueprint-v2/...`. Do not delete or move that package as part of documentation cleanup.

Test only with test-owned sources and bounded workers; don't run paid/GPU generations or unrestricted host tool execution without explicit authorization.

`editor_speech.py` reuses completed correlated ASR jobs and existing Editor plan/clearance/render services. Its API accepts only saved revision, task ID and reviewed segment indices. Unsupported retiming/soundtrack alignment is blocked. No schema migration or new provider is required.
