## Dependency, persistence and boundary

Minimal compiler closure: `minimax_h3_t2v.py` → `minimax_h3_graph_compiler.py` definitions/presets → exact API graph JSON. Readiness closure: `production_t2v_capability.py` → `audio_catalog.comfyui_root()` plus stdlib filesystem/hash/urllib checks; retain its real flag, required files/node names, Comfy URL and smoke-manifest path. Runtime closure expands to `production_job_worker.py`, `production_ledger.py`, `production_take_runtime.py`, `media_jobs.py`, `gpu_runtime.py`, `gpu_watchdog.py`, `production_reconciliation.py`, `production_assets.py`, and their imports/config. Do not claim a one-file service copy.

The project-scoped `validate_and_compile_shot` route (`services/production_shot_validation.py:23–49`) dispatches zero-ref plans directly to `compile_t2v_graph`, so it reuses T2V checks but still carries project/run/shot identity. The general `validate_reference_plan` limits (including 5–15 sec, steps 8–40 and uint32 seed at `minimax_h3_graph_compiler.py:156–175`) are R2V checks and are not automatically applied to T2V. The T2V compiler itself visibly writes steps/seed without validating their bounds. No inspected MiniMax T2V path enforces the product <7000-character prompt requirement; the new isolated validator must. The CPU adapter fixes `steps=20` and `seed=1` for its first slice; editable steps/seed are deferred pending a reviewed T2V capability contract. This is an adapter constraint, not a claim that the T2V compiler enforces those values.

Existing durable store is SQLite at `storage/production/v2_ledger.sqlite3`, overridable by `STORY_BUILDER_PRODUCTION_LEDGER_PATH` (`production_ledger.py:22–23,67–72`). Worker admission depends on a reachable ComfyUI URL, Comfy `/queue`, `/prompt`, `/history`, GPU process/device checks, watchdog support and existing runtime/model/node setup; no GPU/model/runtime files belong in this package. Take outputs currently live under `output/<project_id>/production_v2/runs/...` (`production_take_runtime.py:104–170`), and asset manifests live under injected project storage roots (`production_assets.py:60–104`). Exact env variable names for ComfyUI, output and project storage must be traced at the consuming API/app before extraction; do not invent them here.

Proposed API equivalents (none currently established for isolated T2V):

- `GET /api/video/capabilities?workflow_id=minimax_h3_t2v_local_v1` — thin adapter around local exact workflow readiness. Existing R2V `dynamic_h3_capability()` is explicitly R2V, not equivalent T2V readiness.
- `POST /api/video/validations` — new isolated validation adapter; compiler offers partial checks, but current validation endpoint is shot/project scoped.
- `POST /api/video/jobs` — new durable isolated-job adapter. Existing project V2 take create/retry is an equivalent pattern, with project/run/shot scope, not a direct endpoint match.
- `GET /api/video/jobs/{job_id}` and `GET /api/video/jobs/{job_id}/events` — new isolated retrieval/event shape over durable ledger and Comfy reconciliation. Existing project-scoped take/run GET is analogous.

One idempotency key maps to one application `job_id` and immutable input snapshot; every Comfy submission has reserved `prompt_id`; every output has stable `asset_id` and take/attempt provenance. Browser reconnect performs GET/reconciliation only; it never implicitly POSTs.

## Change boundary and later work

- **Do not copy:** whole Story Builder app, legacy Generate/Production V2 pages, OpenMontage/AGPL code, ComfyUI installation/model weights, media, secrets, node packs, environments, arbitrary workflows, R2V/FLF compilers, or GPU setup.
- **CPU slice implemented in this draft:** exact T2V compiler, shared graph compiler and workflow JSON, plus prompt/settings validation, graph-pinned preview compilation, canonical request hashing and focused tests. It does not include readiness checks or submission.
- **Next durable slice needs:** reuse the existing T2V readiness report; isolated durable owner/ledger contract; one-submit unknown-outcome handling; output persistence/playback URL; immutable retake snapshot with a new attempt/take identity.
- **Later:** frame/reference workflows and manifests, broad capability catalog, prompt editor integrations, screenplay/story links, Media Prep, automation modes, cancellation policy and final assembly. Graph/editor/wrapper adaptation has not been proven surgical.
- **License/notices:** local reference tree has no root license and no Git metadata; the pinned upstream root had no `LICENSE` or `NOTICE`, and the three selected source files have no explicit license header. The owner authorized reuse of their own source for this bounded slice. No third-party implementation was imported. Preserve and confirm notices during canonical integration. OpenMontage source stays excluded pending the plan's explicit AGPL decision.

## Acceptance boundary

The CPU slice verifies exact graph hash, deterministic compilation, validation/errors and canonical request identity. Later CPU work may verify ledger transitions, idempotency, recovery reconciliation and mock output playback metadata. These do not prove local workflow readiness or usable video output. Real-runtime acceptance separately requires supervised ComfyUI/GPU admission, the exact installed graph/nodes/models, completed live smoke, durable output probe/playback, reload recovery and a retake that preserves the original request. This package authorizes neither provider work nor GPU submission.
