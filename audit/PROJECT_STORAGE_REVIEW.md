## Behavior and preservation

One global New/Open/Save project controller owns page context. The selected folder holds a versioned checkpoint and normal output subfolders. Existing application databases, tool sessions and workers remain the operational working copy. Save exports scoped SQL rows, documents, browser memory, registered media and completed tool outputs; Open imports into the existing services. No user-data migration or root replacement ran.

Project IDs, asset identities/hashes, revision IDs and frozen requests remain intact. Active/recovery jobs block checkpoint switching; imported queued/running jobs are rejected. New output preferences do not rewrite existing job requests. Missing original registered media and completed 3D/music outputs can resolve verified checkpoint copies. Referenced ACE datasets/trained adapters travel with the checkpoint; base models/providers/runtime environments remain application-wide.

Editor has typed recursive folder import, library selection/sorting/views, drag attachments and hover/focus removal. ACE opens Create. Video keeps successfully loaded media when another media kind fails, with retry feedback; invalid required references still block generation. Managed project context takes precedence over stale page URLs/keys.

## Limits and practical behavior

- Native folder dialogs, real owner browser/session data, decoded media and provider/GPU generation were not exercised. No generation, model run, user-data move, live-service restart or publication was performed.
- Page families share the controller and persistence adapters, but a complete live A→B→A journey through every tool and full frozen production/assembly run has not been executed. Existing failing legacy fixtures limit wider automated evidence.
- Save retains complete checkpoints, including media copies: repeated saves can consume substantial disk. Old checkpoints are retained; no automatic cleanup was added.
- Reopening a locally registered project preserves newer local work instead of rolling it back. A copied folder with an already-existing conflicting identity is rejected; Save As with a new identity is not exposed.
- Project-internal output grants rebase on a moved folder. External destinations are recorded but require Choose/Locate on a fresh runtime. Shared libraries, secrets, models and provider settings are not packed into projects.
- Import rolls back SQL/new file copies on ordinary precommit failures. Registry writes after SQL commit are retryable but not one filesystem/database transaction; power-loss recovery across both SQLite databases and registries is not fault-injection tested. Concurrent browser tabs still have last-writer memory behavior.
